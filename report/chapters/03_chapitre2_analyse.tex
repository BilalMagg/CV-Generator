Les solutions existantes présentent plusieurs limitations :
\begin{itemize}
    \item \textbf{Personnalisation limitée :} La plupart des outils offrent des modèles fixes sans adaptation réelle au contenu de l'offre d'emploi.
    \item \textbf{Absence de suivi intégré :} Aucune solution ne combine la génération de CV avec le suivi des candidatures dans une plateforme unifiée.
    \item \textbf{Coût :} Les solutions avancées sont payantes (abonnements mensuels).
    \item \textbf{Optimisation ATS limitée :} Peu d'outils optimisent réellement le CV pour passer les filtres des systèmes ATS.
\end{itemize}

\projectname{} se distingue en offrant une solution complète, gratuite et open source, combinant génération IA de CV, optimisation ATS et suivi de candidatures.

\section{Étude des besoins non fonctionnels}
\label{sec:analyse:non-fonctionnels}

Les besoins non fonctionnels identifiés sont :

\begin{itemize}
    \item \textbf{Performance :} La génération d'un CV ne doit pas excéder quelques secondes. Les temps de réponse de l'API doivent être optimisés.
    \item \textbf{Sécurité :} L'authentification doit être centralisée via Keycloak avec support OAuth2 et OpenID Connect. Les communications doivent être chiffrées (HTTPS). Les vulnérabilités doivent être scannées via Trivy et OWASP ZAP.
    \item \textbf{Disponibilité :} Le système doit être résilient grâce à une architecture en microservices et une orchestration Docker. Les services critiques doivent pouvoir redémarrer automatiquement.
    \item \textbf{Maintenabilité :} Le code source doit être organisé en modules séparés, versionné avec Git, et suivre les principes SOLID. La qualité du code est surveillée via SonarCloud.
    \item \textbf{Évolutivité :} L'architecture microservices permet de faire évoluer chaque service indépendamment. L'utilisation de Kafka permet un couplage faible entre les services.
    \item \textbf{Ergonomie :} L'interface utilisateur doit être intuitive, responsive et suivre une charte graphique cohérente (design system Propel).
    \item \textbf{Portabilité :} L'ensemble de l'application doit être conteneurisée avec Docker pour garantir un déploiement reproductible sur n'importe quel environnement.
\end{itemize}

\subsection{Modèle relationnel de la base de données}
\label{subsec:analyse:bdd}

L'architecture microservices du projet implique l'utilisation de plusieurs bases de données PostgreSQL 16, une par service. Chaque base de données est spécialisée pour les besoins de son service et réside dans un conteneur Docker dédié. L'extension pgvector est utilisée pour le support des recherches vectorielles dans les bases concernées par le pipeline IA.

\subsubsection*{Base Utilisateurs (user-db — port 5433)}
\label{subsubsec:bdd:user}

La base utilisateurs centralise les informations personnelles et professionnelles des candidats.

\begin{itemize}
    \item \texttt{users} : Table principale contenant le profil complet de chaque utilisateur. Les attributs incluent \texttt{keycloakId} (identifiant de synchronisation avec Keycloak), \texttt{headline} (titre professionnel), \texttt{desiredSalaryMin/desiredSalaryMax} (prétentions salariales), \texttt{requiresVisaSponsorship}, \texttt{noticePeriod} (préavis), \texttt{employmentTypes} (types d'emploi souhaités), \texttt{remotePreference} (préférence de télétravail), \texttt{willingToRelocate} (mobilité géographique). Des colonnes JSON permettent de stocker des données flexibles : \texttt{preferencesJson} et \texttt{aiProfileDataJson} (profil généré par l'IA).
\end{itemize}

\subsubsection*{Base Contenu Utilisateur (content-db — port 5434)}
\label{subsubsec:bdd:content}

Cette base gère l'ensemble du portfolio de l'utilisateur. Chaque table est reliée à l'utilisateur via une clé étrangère \texttt{userId}.

\begin{itemize}
    \item \texttt{projects} : Projets réalisés. L'attribut \texttt{skillsJson} stocke les compétences associées sous forme JSON. \texttt{repositoryUrl} et \texttt{demoUrl} pointent vers les sources et démonstrations.
    \item \texttt{skills} : Compétences avec \texttt{category} (langage, framework, outil), \texttt{level} (débutant, intermédiaire, avancé, expert) et \texttt{yearsOfExperience}.
    \item \texttt{experiences} : Expériences professionnelles avec \texttt{company} et \texttt{status} (en cours, terminée).
    \item \texttt{educations} : Formations avec \texttt{degreeType} (licence, master, doctorat), \texttt{fieldOfStudy} et \texttt{specialization}. \texttt{diplomaFileUrl} stocke le lien vers le fichier du diplôme.
    \item \texttt{certifications} : Certifications avec \texttt{issuingOrganization} et \texttt{credentialUrl}.
    \item \texttt{languages} : Langues avec \texttt{level} (A1 à C2).
    \item \texttt{interests} : Centres d'intérêt.
    \item \texttt{hackathons} : Participations à des hackathons avec \texttt{role}, \texttt{result} et \texttt{description}.
    \item \texttt{socialLinks} : Liens vers les réseaux sociaux (\texttt{platform}, \texttt{url}).
    \item \texttt{cvProfiles} : Profils de CV avec \texttt{summary} (résumé personnel) et \texttt{title}.
    \item \texttt{academicActivities} : Activités académiques (projets scolaires, publications) avec période.
\end{itemize}

\subsubsection*{Base Candidatures (application-db — port 5436)}
\label{subsubsec:bdd:application}

Cette base assure le suivi des candidatures des utilisateurs.

\subsubsection*{Base Workflow (workflow-db — port 5435)}
\label{subsubsec:bdd:workflow}

La base workflow est la plus complexe. Elle pilote le pipeline de génération de CV et utilise pgvector pour les recherches vectorielles.

\begin{itemize}
    \item \texttt{workflows} : Définition des pipelines. \texttt{definitionJson} contient la configuration du workflow au format JSON. \texttt{isActive} active ou désactive le pipeline.
    \item \texttt{cvGenerationRuns} : Traces d'exécution de chaque génération de CV. \texttt{jobDescription} stocke le texte brut de l'offre. \texttt{status} suit l'état (\texttt{pending}, \texttt{running}, \texttt{completed}, \texttt{failed}, \texttt{cancelled}). \texttt{stepStatuses} est un champ JSON contenant l'état de chaque étape. Les résultats des agents sont stockés dans des colonnes dédiées : \texttt{extractionResult}, \texttt{searchResult}, \texttt{renderResult}, \texttt{optimizationResult}, \texttt{deliveryResult}.
    \item \texttt{agents} : Configuration des agents IA. \texttt{agentId} est un identifiant unique (ex: \texttt{job-extractor}). \texttt{sortOrder} détermine l'ordre d'exécution dans le pipeline. \texttt{backgroundGradient} est utilisé pour l'affichage dans l'interface.
    \item \texttt{agentDocumentChunks} : Stockage des documents vectorisés pour le RAG. \texttt{sourceId} et \texttt{sourceType} identifient l'entité source. \texttt{embedding} est un vecteur pgvector utilisé pour la recherche sémantique. \texttt{searchVector} est un tsvector pour la recherche full-text.
    \item \texttt{jobExtractions} : Extractions d'offres d'emploi. \texttt{inputType} distingue le texte saisi de l'URL. \texttt{confidence} est un score de confiance de l'extraction. \texttt{outputJson} contient le résultat structuré.
    \item \texttt{workflowProjects}, \texttt{workflowSkills}, \texttt{workflowExperiences} : Entités miroir du contenu utilisateur, optimisées pour la recherche vectorielle avec des champs \texttt{embedding} et \texttt{aiSummaryJson}.
\end{itemize}

\subsubsection*{Base Offres d'Emploi (job-offer-db — port 5437)}
\label{subsubsec:bdd:job-offer}

Cette base stocke les offres d'emploi collectées par l'agent de crawling et enrichies par l'agent d'extraction.

\begin{itemize}
    \item \texttt{jobOffers} : Offres d'emploi. \texttt{jobHash} est un hash unique de l'offre pour éviter les doublons lors du crawling. \texttt{sourceUrl} est l'URL d'origine. \texttt{rawDescription} stocke la description brute. \texttt{descriptionVector} est un vecteur pgvector pour le matching avec le profil utilisateur. \texttt{locationType} distingue \texttt{remote}, \texttt{onsite} et \texttt{hybrid}. \texttt{employmentType} (\texttt{full-time}, \texttt{part-time}, \texttt{contract}) et \texttt{seniorityLevel} (\texttt{junior}, \texttt{mid}, \texttt{senior}, \texttt{lead}) qualifient le poste.
    \item \texttt{jobSkills} : Compétences requises pour le poste. \texttt{type} distingue les compétences \texttt{required} et \texttt{preferred}. \texttt{isMandatory} indique si la compétence est obligatoire.
    \item \texttt{jobResponsibilities} : Liste des responsabilités du poste.
    \item \texttt{jobBenefits} : Avantages proposés par l'entreprise.
    \item \texttt{searchCaches} : Cache des recherches de crawling. \texttt{keyword} et \texttt{location} définissent la recherche. \texttt{status} suit l'avancement. \texttt{expectedCount} et \texttt{processedCount} permettent de suivre le nombre d'offres traitées.
    \item \texttt{userQuotas} : Quotas de crawling par utilisateur. \texttt{lastCrawlDate} enregistre la dernière date d'utilisation.
\end{itemize}

    \item \texttt{cvSections} : Sections d'une version de CV. \texttt{sectionType} définit le type (\texttt{education}, \texttt{experience}, \texttt{skills}, \texttt{projects}, \texttt{certifications}, \texttt{languages}). \texttt{contentJson} contient les données de la section. \texttt{displayOrder} détermine l'ordre d'affichage.

\subsubsection*{Base Notifications (notification-db — port 5438)}
\label{subsubsec:bdd:notification}

Cette base gère l'ensemble du système de notifications, de rappels et de messagerie.

\begin{itemize}
    \item \texttt{notifications} : Notifications in-app et email. \texttt{type} définit la catégorie (\texttt{application\_update}, \texttt{cv\_ready}, \texttt{reminder}, \texttt{welcome}). \texttt{channel} détermine le mode (\texttt{email}, \texttt{in-app}). \texttt{isRead} et \texttt{isSent} tracent l'état. \texttt{errorMessage} enregistre les échecs d'envoi.
    \item \texttt{notificationPreferences} : Préférences de notification par utilisateur. \texttt{enableEmail} et \texttt{enableInApp} activent les canaux. \texttt{applicationUpdates}, \texttt{cvUpdates}, \texttt{reminders}, \texttt{weeklyDigest} activent les catégories. \texttt{defaultReminderDaysBefore} définit le délai de rappel par défaut.
    \item \texttt{reminders} : Rappels planifiés. \texttt{eventDate} est la date de l'événement, \texttt{reminderAt} est la date du rappel. \texttt{reminderOffset} définit le décalage (ex: \texttt{1d}, \texttt{2h}). \texttt{status} suit l'état (\texttt{pending}, \texttt{sent}, \texttt{cancelled}).
    \item \texttt{contacts} : Carnet d'adresses. \texttt{source} indique la provenance (manuel, import Gmail). \texttt{isFavorite} permet de marquer les contacts favoris. \texttt{avatarBase64} stocke l'avatar encodé.
    \item \texttt{emailMessages} : Historique des emails envoyés. \texttt{provider} indique le fournisseur (MailKit, Gmail API). \texttt{status} suit la délivrabilité. \texttt{contactId} relie l'email à un contact. \texttt{scheduleId} permet de lier à une campagne planifiée.
    \item \texttt{emailSchedules} : Campagnes d'emails planifiées. \texttt{cronExpression} définit la récurrence. \texttt{recipientIds} stocke les destinataires. \texttt{isActive} active ou désactive la campagne.
    \item \texttt{gmailConnections} : Connexions Gmail des utilisateurs. \texttt{encryptedAccessToken} et \texttt{encryptedRefreshToken} stockent les jetons OAuth chiffrés. \texttt{isRevoked} indique si la connexion a été révoquée.
\end{itemize}
